## The fix's new rules across the two docs

The two docs agree on these:

- `__typename` read on call 3 (F-07) and call 2 (F-17).
- The kept answer: every error `NOT_FOUND`, with `path` `["repository", alias]`, on an alias given as `null`.
- An issue clears when closed for any of three reasons. A pull request clears only when merged.
- A pull request closed unmerged holds until the `Blocked by:` line is edited, with the owner's words.
- An unknown number holds its leaf, compared with a run where that number is an open issue.
- Findings or lines go on open leaves only.
- The unknown-blocker text has the same first two sentences, with `{list}` capped at three numbers.
- A not-found item issue reads `#n not found` and never blanks the read.

The owner's two answers of 2026-11-04 are both written in F-07. A pull request closed unmerged holds, and the leaf
carries "PR #{n} closed unmerged; check the wait." (194–195, 352–353). These words match F-18
(`dev/features/milestone-board.md:237`–`238`). A not-found item issue shows "#n not found" (172), and the kept-answer
rule keeps it (160–162).

They differ in two places:

- the closed-unmerged line's form (AR-2 below);
- the words of the kept-answer rule. F-07 keeps a `NOT_FOUND` on any `null` alias. F-17 keeps it only on an
  item-issue alias or a `p{n}` alias, and says `realGh()` decides. That is the F-17 0.5 review's AR-3. Every answer
  asked above gives the same result under either wording.

### AR-2 — The closed-unmerged finding has two forms across the docs
